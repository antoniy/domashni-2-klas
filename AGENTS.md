# Домашни – 2. клас

Учителят дава задачите като текст; тук те се превръщат в PDF за печат.
Репото е публично: линковете към PDF-ите се споделят.

## Структура
- `homework/YYYY-MM-DD.toml` – задачите за деня (източникът).
- `pdf/YYYY-MM-DD.pdf` – генериран файл, името идва от TOML файла. Комитва се, за да има линк.
- `scripts/build.py` – TOML → PDF.

## Нова информация за домашно → PDF → commit → push
Важи за нова домашна, допълнение или поправка от учителя. Цялата поредица се изпълнява без допълнително питане; commit и push са част от нея.

1. **Дата** = денят, в който учителят е дал домашната; ако не е казана, днешната. Втора, отделна домашна за същия ден: `YYYY-MM-DD-2`.
2. **TOML:**
   - Нова домашна: създай `homework/<дата>.toml` по модела на съществуващ файл.
   - Допълнение или поправка към вече дадена: редактирай съществуващия `homework/<дата>.toml`, не прави нов файл.
   - Задача, която не пасва на нито един тип от таблицата: първо разшири скрипта по „Нов тип задача“ по-долу, после продължи.
3. **Генерирай:**
   ```bash
   python3 -m venv .venv && .venv/bin/pip install -r requirements.txt   # само ако няма .venv
   .venv/bin/python scripts/build.py homework/<дата>.toml
   ```
4. **Провери визуално:** `pdftoppm -r 60 -png pdf/<дата>.pdf <временна папка>/p` и разгледай всяка страница. Без излишни страници „(продължение)“, ако съдържанието може да се събере. Проблем → поправи и генерирай пак; не комитвай непроверен PDF.
5. **Commit** – само TOML и PDF файла за тази дата (плюс `scripts/build.py` и този файл, ако са променени за задачата):
   ```bash
   git add homework/<дата>.toml pdf/<дата>.pdf
   git commit -m "Домашна <дата>"        # поправка: "Поправка домашна <дата>: <какво>"
                                         # нов тип: "Домашна <дата>, нов тип задача <type>"
   ```
6. **Push:**
   ```bash
   GH_TOKEN=$(gh auth token --user antoniy) git push
   ```
   Push отказан (напр. remote има нови commit-и): `GH_TOKEN=... git pull --rebase`, после push. Без `--force`.
7. **Провери линка:** `curl -sIL -o /dev/null -w '%{http_code}' https://github.com/antoniy/domashni-2-klas/raw/main/pdf/<дата>.pdf` трябва да върне `200`.
8. **Отговор към потребителя:** линк за преглед и линк за сваляне, плюс всяка поправка на текста на учителя.

## Съдържание
- Текстът на учителя се копира дословно. Поправят се само очевидни печатни грешки в интервалите (напр. `65 –6` → `65 – 6`); всяка поправка се казва на потребителя.
- Без отговори и решения в PDF-а.
- Без лични данни (име на детето, училище, учител) – репото е публично. Полетата „Име“ и „Дата“ остават празни.
- Всеки предмет започва на нова страница.

## Типове задачи (`type` в TOML)
| type | полета | какво рисува |
|---|---|---|
| `sentences` | `words`, `lines` (по подразбиране 2) | дума + редове за изречение |
| `calc` | `expressions`, `columns` (4) | израз + квадратче за отговор |
| `word_problems` | `problems`, `sections` (Кратък запис 3, Решение 2, Отговор 1) | текст на задачата + редове с надписи |

## Нов тип задача
Учителят ще дава и задачи, за които скриптът няма тип. Тогава агентът сам разширява скрипта – не пита и не натъпква задачата в неподходящ тип.

**1. Пасва ли на съществуващ тип с други параметри?** Напр. „Препишете думите“ = `sentences` с `lines = 1`; сметки със събиране = `calc`. Ако да – без нов код.

**2. Какво трябва да прави детето на листа?** Оттам идва оформлението:
| Задачата иска | Оформление |
|---|---|
| кратък отговор (число, дума) | квадратче или къса линия до въпроса |
| изречение / текст | редове за писане, колкото е нужно за отговора |
| попълване на пропуски | текстът с линия на мястото на пропуска |
| избор / свързване / ограждане | отговорите подредени в колони, с място за отбелязване |
| рисуване, схема, сравняване (<, >, =) | рамка или квадратче с достатъчно място |
| таблица | истинска таблица с клетки за попълване |

**3. Добави тип в `scripts/build.py`:**
- Функция `task_<име>(s, t)`: `s` е листът, `t` е задачата от TOML. Впиши я в `TASKS`.
- Ползвай наличното: `s.paragraph()` за текст, `s.labelled_lines()` и `s.rule()` за редове, `s.ensure(височина)` преди всеки блок (сам прави нова страница при нужда), `LINE_GAP`, `LABEL`, `RULE`, `BLACK`, шрифтове `Body` и `Body-Bold`.
- Параметрите на задачата идват от TOML, със смислени стойности по подразбиране (`t.get(...)`).
- Номерът и условието на задачата ги рисува общият код; функцията рисува само тялото.
- Добави реда в таблицата „Типове задачи“.

**4. Качество – провери на картинката, преди commit:**
- Детето разбира какво да прави без обяснение; всяко място за отговор е ясно къде е.
- Място за писане: редове поне `LINE_GAP` (9.5 mm), квадратчета поне 12 × 9 mm.
- Същите шрифтове, размери и отстъпи като другите типове – листът изглежда като едно цяло.
- Само черно и тъмносиво; нищо не се застъпва и не излиза от полетата.
- Колкото може по-малко страници, без да се стеснява мястото за писане.

**5. Старите домашни не трябва да се променят.** Генерирането е детерминирано (еднакъв вход → байт по байт еднакъв PDF), така че:
```bash
for f in homework/*.toml; do .venv/bin/python scripts/build.py "$f"; done
git status --short pdf/
```
Трябва да се вижда само PDF-ът на новата домашна. Променен стар PDF = новият код е счупил нещо → поправи кода, не комитвай старите файлове.
